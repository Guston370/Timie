# Design Document: Timetable Generator Android App

## Overview

The Timetable Generator Android App implements a constraint satisfaction problem (CSP) solver for academic scheduling. The system uses a backtracking algorithm with constraint propagation to generate valid timetables that satisfy hard constraints (no conflicts) and optimize soft constraints (preferences). The architecture follows MVVM pattern with clear separation between UI, business logic, and data layers.

The core algorithm places assignments (subject, faculty, room) into time slots (day, period) while checking constraints at each step. When conflicts arise, the algorithm backtracks and tries alternative assignments. Multiple timetable variants are generated by varying the optimization heuristics (balanced distribution, compactness, faculty preferences).

## Architecture

### MVVM Pattern

**Model Layer:**
- POJOs representing domain entities (Subject, Faculty, Room, TimeSlot, Assignment)
- Constraint validators
- Timetable data structures

**ViewModel Layer:**
- Manages UI state using LiveData
- Coordinates between Repository and UI
- Handles user actions and updates

**View Layer:**
- Activities and Fragments for each screen
- XML layouts
- RecyclerView adapters for lists and grids

**Repository Layer:**
- In-memory data storage during session
- Optional Room Database integration for persistence
- Data access abstraction

**Algorithm Layer:**
- Constraint satisfaction solver
- Backtracking engine
- Heuristic strategies for variant generation

**Constraint Implementations:**

```java
public class NoFacultyDoubleBookingConstraint implements Constraint {
    @Override
    public boolean isSatisfied(Assignment assignment, Timetable currentTimetable) {
        // Check if faculty is already assigned at this time slot
        Map<TimeSlot, Assignment> facultySchedule = 
            currentTimetable.getFacultyTimetables().get(assignment.getFacultyId());
        
        if (facultySchedule == null) return true;
        
        return !facultySchedule.containsKey(assignment.getTimeSlot());
    }
}

public class FacultyWorkloadConstraint implements Constraint {
    @Override
    public boolean isSatisfied(Assignment assignment, Timetable currentTimetable) {
        // Count faculty's periods on this day
        int day = assignment.getTimeSlot().getDay();
        Map<TimeSlot, Assignment> facultySchedule = 
            currentTimetable.getFacultyTimetables().get(assignment.getFacultyId());
        
        if (facultySchedule == null) return true;
        
        long periodsToday = facultySchedule.keySet().stream()
            .filter(slot -> slot.getDay() == day)
            .count();
        
        Faculty faculty = repository.getFaculty(assignment.getFacultyId());
        return periodsToday < faculty.getMaxPeriodsPerDay();
    }
}

public class LabConsecutiveConstraint implements Constraint {
    @Override
    public boolean isSatisfied(Assignment assignment, Timetable currentTimetable) {
        Subject subject = repository.getSubject(assignment.getSubjectId());
        
        if (subject.getType() != SubjectType.LAB) return true;
        
        // Lab must be placed in consecutive periods
        // Check if next period is available for same assignment
        TimeSlot nextSlot = new TimeSlot(
            assignment.getTimeSlot().getDay(),
            assignment.getTimeSlot().getPeriod() + 1
        );
        
        // Verify next slot is free for this class, faculty, and room
        return isSlotAvailable(nextSlot, assignment, currentTimetable);
    }
}

public class RoomDoubleBookingConstraint implements Constraint {
    @Override
    public boolean isSatisfied(Assignment assignment, Timetable currentTimetable) {
        // Check if room is already booked at this time slot
        for (Assignment existing : currentTimetable.getAllAssignments()) {
            if (existing.getRoomId().equals(assignment.getRoomId()) &&
                existing.getTimeSlot().equals(assignment.getTimeSlot())) {
                return false;
            }
        }
        return true;
    }
}

public class SubjectRepetitionConstraint implements Constraint {
    @Override
    public boolean isSatisfied(Assignment assignment, Timetable currentTimetable) {
        Subject subject = repository.getSubject(assignment.getSubjectId());
        
        if (subject.isAllowRepetition()) return true;
        
        // Check if subject already scheduled for this class on this day
        int day = assignment.getTimeSlot().getDay();
        Map<TimeSlot, Assignment> classSchedule = 
            currentTimetable.getClassTimetables().get(assignment.getClassSectionId());
        
        if (classSchedule == null) return true;
        
        return classSchedule.entrySet().stream()
            .noneMatch(entry -> 
                entry.getKey().getDay() == day &&
                entry.getValue().getSubjectId().equals(assignment.getSubjectId())
            );
    }
}

public class FacultyAvailabilityConstraint implements Constraint {
    @Override
    public boolean isSatisfied(Assignment assignment, Timetable currentTimetable) {
        Faculty faculty = repository.getFaculty(assignment.getFacultyId());
        TimeSlot slot = assignment.getTimeSlot();
        
        Map<Integer, List<Integer>> availability = faculty.getAvailability();
        
        if (!availability.containsKey(slot.getDay())) return false;
        
        return availability.get(slot.getDay()).contains(slot.getPeriod());
    }
}
```

**BacktrackingSolver.java**
```java
public class BacktrackingSolver {
    private ConstraintChecker constraintChecker;
    private TimetableRepository repository;
    private Config config;
    private HeuristicStrategy strategy;
    
    public Timetable solve(HeuristicStrategy strategy) {
        this.strategy = strategy;
        Timetable timetable = new Timetable();
        
        // Initialize empty timetable
        initializeTimetable(timetable);
        
        // Block break periods
        blockBreakPeriods(timetable);
        
        // Get all assignments to place
        List<Assignment> assignmentsToPlace = generateAssignments();
        
        // Sort by strategy heuristic
        assignmentsToPlace = strategy.sortAssignments(assignmentsToPlace);
        
        // Backtracking search
        if (backtrack(timetable, assignmentsToPlace, 0)) {
            return timetable;
        }
        
        return null; // No solution found
    }
    
    private boolean backtrack(Timetable timetable, List<Assignment> assignments, int index) {
        if (index >= assignments.size()) {
            return validateCompleteTimetable(timetable);
        }
        
        Assignment assignment = assignments.get(index);
        
        // Try all possible time slots
        for (TimeSlot slot : getAllPossibleSlots()) {
            assignment.setTimeSlot(slot);
            
            if (constraintChecker.checkAllConstraints(assignment, timetable)) {
                // Place assignment
                timetable.addAssignment(assignment);
                
                // Recurse
                if (backtrack(timetable, assignments, index + 1)) {
                    return true;
                }
                
                // Backtrack
                timetable.removeAssignment(assignment);
            }
        }
        
        return false;
    }
    
    private List<Assignment> generateAssignments() {
        List<Assignment> assignments = new ArrayList<>();
        
        for (ClassSection classSection : repository.getAllClassSections()) {
            for (Subject subject : repository.getAllSubjects()) {
                // Create assignments for each required period
                for (int i = 0; i < subject.getWeeklyPeriods(); i++) {
                    Assignment assignment = new Assignment();
                    assignment.setSubjectId(subject.getId());
                    assignment.setClassSectionId(classSection.getId());
                    
                    // Find faculty who can teach this subject
                    Faculty faculty = findAvailableFaculty(subject);
                    assignment.setFacultyId(faculty.getId());
                    
                    // Find appropriate room
                    Room room = findAppropriateRoom(subject);
                    assignment.setRoomId(room.getId());
                    
                    assignments.add(assignment);
                }
            }
        }
        
        return assignments;
    }
    
    private List<TimeSlot> getAllPossibleSlots() {
        List<TimeSlot> slots = new ArrayList<>();
        for (int day = 0; day < config.getWorkingDays(); day++) {
            for (int period = 0; period < config.getPeriodsPerDay(); period++) {
                if (!config.getBreakPeriods().contains(period)) {
                    slots.add(new TimeSlot(day, period));
                }
            }
        }
        return slots;
    }
}
```

**BalancedStrategy.java**
```java
public class BalancedStrategy implements HeuristicStrategy {
    @Override
    public List<Assignment> sortAssignments(List<Assignment> assignments) {
        // Sort by priority, then by subject type (labs first)
        assignments.sort((a1, a2) -> {
            Subject s1 = repository.getSubject(a1.getSubjectId());
            Subject s2 = repository.getSubject(a2.getSubjectId());
            
            // Labs first
            if (s1.getType() == SubjectType.LAB && s2.getType() != SubjectType.LAB) {
                return -1;
            }
            if (s1.getType() != SubjectType.LAB && s2.getType() == SubjectType.LAB) {
                return 1;
            }
            
            // Then by priority
            return s1.getPriority().compareTo(s2.getPriority());
        });
        
        return assignments;
    }
    
    @Override
    public TimeSlot selectBestSlot(Assignment assignment, List<TimeSlot> availableSlots) {
        // Select slot that balances distribution across days
        Map<Integer, Integer> dayLoad = calculateDayLoad();
        
        return availableSlots.stream()
            .min(Comparator.comparingInt(slot -> dayLoad.get(slot.getDay())))
            .orElse(availableSlots.get(0));
    }
}
```

**CompactStrategy.java**
```java
public class CompactStrategy implements HeuristicStrategy {
    @Override
    public TimeSlot selectBestSlot(Assignment assignment, List<TimeSlot> availableSlots) {
        // Prefer slots that minimize gaps
        // Select earliest available slot on days with existing assignments
        return availableSlots.stream()
            .filter(slot -> hasAdjacentAssignment(slot, assignment))
            .findFirst()
            .orElse(availableSlots.get(0));
    }
}
```

**FacultyFriendlyStrategy.java**
```java
public class FacultyFriendlyStrategy implements HeuristicStrategy {
    @Override
    public TimeSlot selectBestSlot(Assignment assignment, List<TimeSlot> availableSlots) {
        Faculty faculty = repository.getFaculty(assignment.getFacultyId());
        
        if (faculty.isAvoidConsecutive()) {
            // Filter out slots adjacent to existing faculty assignments
            return availableSlots.stream()
                .filter(slot -> !hasAdjacentFacultyAssignment(slot, faculty))
                .findFirst()
                .orElse(availableSlots.get(0));
        }
        
        return availableSlots.get(0);
    }
}
```

**TimetableGenerator.java**
```java
public class TimetableGenerator {
    private BacktrackingSolver solver;
    private TimetableRepository repository;
    
    public List<Timetable> generateVariants() {
        List<Timetable> variants = new ArrayList<>();
        
        // Generate Balanced variant
        Timetable balanced = solver.solve(new BalancedStrategy());
        if (balanced != null) {
            balanced.setVariantName("Balanced");
            variants.add(balanced);
        }
        
        // Generate Compact variant
        Timetable compact = solver.solve(new CompactStrategy());
        if (compact != null) {
            compact.setVariantName("Compact");
            variants.add(compact);
        }
        
        // Generate Faculty-friendly variant
        Timetable facultyFriendly = solver.solve(new FacultyFriendlyStrategy());
        if (facultyFriendly != null) {
            facultyFriendly.setVariantName("Faculty-friendly");
            variants.add(facultyFriendly);
        }
        
        return variants;
    }
    
    public Timetable regenerateWithLockedSlots(Timetable existing, List<TimeSlot> lockedSlots) {
        // Create new timetable with locked assignments
        Timetable newTimetable = new Timetable();
        
        // Copy locked assignments
        for (Assignment assignment : existing.getAllAssignments()) {
            if (assignment.isLocked()) {
                newTimetable.addAssignment(assignment);
            }
        }
        
        // Generate assignments for unlocked slots
        List<Assignment> unlockedAssignments = generateUnlockedAssignments(existing, lockedSlots);
        
        // Solve with locked constraints
        return solver.solveWithFixed(newTimetable, unlockedAssignments);
    }
}
```

### ViewModel Layer

**GenerationViewModel.java**
```java
public class GenerationViewModel extends ViewModel {
    private TimetableGenerator generator;
    private TimetableRepository repository;
    
    private MutableLiveData<List<Timetable>> timetables = new MutableLiveData<>();
    private MutableLiveData<Boolean> isGenerating = new MutableLiveData<>();
    private MutableLiveData<ConflictReport> conflicts = new MutableLiveData<>();
    
    public void generateTimetables() {
        isGenerating.setValue(true);
        
        // Run on background thread
        new Thread(() -> {
            try {
                List<Timetable> variants = generator.generateVariants();
                
                if (variants.isEmpty()) {
                    ConflictReport report = new ConflictReport();
                    report.addConflict("Unable to generate valid timetable with current constraints");
                    conflicts.postValue(report);
                } else {
                    timetables.postValue(variants);
                }
            } catch (Exception e) {
                ConflictReport report = new ConflictReport();
                report.addConflict("Generation failed: " + e.getMessage());
                conflicts.postValue(report);
            } finally {
                isGenerating.postValue(false);
            }
        }).start();
    }
    
    public LiveData<List<Timetable>> getTimetables() {
        return timetables;
    }
    
    public LiveData<Boolean> getIsGenerating() {
        return isGenerating;
    }
    
    public LiveData<ConflictReport> getConflicts() {
        return conflicts;
    }
}
```

**TimetableViewModel.java**
```java
public class TimetableViewModel extends ViewModel {
    private TimetableRepository repository;
    private ConstraintChecker constraintChecker;
    
    private MutableLiveData<Timetable> currentTimetable = new MutableLiveData<>();
    private MutableLiveData<ConflictReport> editConflicts = new MutableLiveData<>();
    
    public void swapAssignments(Assignment a1, Assignment a2) {
        Timetable timetable = currentTimetable.getValue();
        
        // Temporarily swap
        TimeSlot temp = a1.getTimeSlot();
        a1.setTimeSlot(a2.getTimeSlot());
        a2.setTimeSlot(temp);
        
        // Validate
        boolean valid = constraintChecker.checkAllConstraints(a1, timetable) &&
                       constraintChecker.checkAllConstraints(a2, timetable);
        
        if (valid) {
            currentTimetable.setValue(timetable);
        } else {
            // Revert swap
            a1.setTimeSlot(a2.getTimeSlot());
            a2.setTimeSlot(temp);
            
            ConflictReport report = new ConflictReport();
            report.setConflicts(constraintChecker.getViolations(a1, timetable));
            editConflicts.setValue(report);
        }
    }
    
    public void lockAssignment(Assignment assignment) {
        assignment.setLocked(true);
        currentTimetable.setValue(currentTimetable.getValue());
    }
}
```

## Data Models

### Timetable Data Structure

The timetable is represented as a nested map structure:

```
Timetable
├── classTimetables: Map<ClassSectionId, Map<TimeSlot, Assignment>>
├── facultyTimetables: Map<FacultyId, Map<TimeSlot, Assignment>>
└── allAssignments: List<Assignment>
```

This structure allows O(1) lookup for:
- Finding what's scheduled for a class at a specific time
- Finding what a faculty member is teaching at a specific time
- Checking room availability at a specific time

### Assignment Structure

Each assignment represents a single teaching period:

```
Assignment
├── subjectId: String
├── facultyId: String
├── roomId: String
├── classSectionId: String
├── timeSlot: TimeSlot (day, period)
└── locked: boolean
```

## Correctness Properties

*A property is a characteristic or behavior that should hold true across all valid executions of a system—essentially, a formal statement about what the system should do. Properties serve as the bridge between human-readable specifications and machine-verifiable correctness guarantees.*

### Core Constraint Properties

**Property 1: No Faculty Double-Booking**
*For any* generated timetable, no faculty member should be assigned to teach two different classes at the same time slot.
**Validates: Requirements 6.1**

**Property 2: Faculty Workload Limits**
*For any* generated timetable and any faculty member, the number of periods assigned to that faculty on any single day should not exceed their configured maximum periods per day.
**Validates: Requirements 6.2**

**Property 3: Subject Weekly Period Count**
*For any* generated timetable and any subject, the total number of periods assigned to that subject across all classes should exactly match the subject's required weekly period count.
**Validates: Requirements 6.3**

**Property 4: Lab Consecutive Periods**
*For any* generated timetable and any Lab subject assignment, the Lab periods should be allocated in consecutive time slots (same day, adjacent periods).
**Validates: Requirements 2.7, 6.4**

**Property 5: Break Periods Unassigned**
*For any* generated timetable, all time slots designated as break periods should have no teaching assignments.
**Validates: Requirements 6.5, 7.2**

**Property 6: No Room Double-Booking**
*For any* generated timetable, no room should be assigned to two different classes at the same time slot.
**Validates: Requirements 6.6**

**Property 7: Subject Repetition Constraint**
*For any* generated timetable, any subject with repetition disabled should not be scheduled more than once on the same day for the same class section.
**Validates: Requirements 6.7**

**Property 8: Faculty Availability Constraint**
*For any* generated timetable and any faculty member, all assignments for that faculty should only occur during their configured available time slots.
**Validates: Requirements 6.8**

### Validation and Input Properties

**Property 9: Configuration Validation**
*For any* configuration with break periods, at least one non-break teaching period should exist per day.
**Validates: Requirements 1.7**

**Property 10: Subject Data Validation**
*For any* subject with incomplete data (missing name, invalid weekly period count, or missing type), the validation should reject the subject and prevent proceeding.
**Validates: Requirements 2.8**

**Property 11: Faculty Data Validation**
*For any* faculty with incomplete data (missing name, empty subject list, or invalid max periods), the validation should reject the faculty and prevent proceeding.
**Validates: Requirements 3.7**

### Generation and Variant Properties

**Property 12: Variant Generation Count**
*For any* successful timetable generation, the system should produce exactly three timetable variants (Balanced, Compact, Faculty-friendly).
**Validates: Requirements 7.8**

**Property 13: Balanced Distribution**
*For any* timetable generated with the Balanced strategy, subjects for each class should be distributed across days such that the variance in daily subject counts is minimized.
**Validates: Requirements 18.1**

**Property 14: Compact Schedule**
*For any* timetable generated with the Compact strategy, the number of free periods between assigned periods should be minimized compared to other strategies.
**Validates: Requirements 18.2**

**Property 15: Faculty-Friendly Scheduling**
*For any* timetable generated with the Faculty-friendly strategy and any faculty member with avoidConsecutive preference enabled, that faculty should have no consecutive period assignments.
**Validates: Requirements 18.3**

### Editing and Regeneration Properties

**Property 16: Swap Constraint Validation**
*For any* proposed swap of two assignments in a timetable, the swap should be rejected if and only if it would violate any constraint (faculty double-booking, room double-booking, faculty workload, faculty availability, or subject repetition).
**Validates: Requirements 11.4**

**Property 17: Locked Slots Preservation**
*For any* timetable regeneration with locked slots, all assignments marked as locked should remain unchanged in the regenerated timetable.
**Validates: Requirements 12.1, 12.2**

### Reporting and Display Properties

**Property 18: Cell Rendering Completeness**
*For any* non-empty, non-break timetable cell, the rendered display should include the subject name, faculty name, and room name.
**Validates: Requirements 8.2**

**Property 19: Faculty Schedule Rendering**
*For any* faculty schedule display and any assigned period, the rendered display should include the class name, section name, subject name, and room name.
**Validates: Requirements 9.2**

**Property 20: Faculty Workload Calculation**
*For any* faculty schedule display, the calculated daily workload should equal the count of assigned periods for that faculty on that day.
**Validates: Requirements 9.3**

**Property 21: Conflict Report Completeness**
*For any* constraint violation, the conflict report should identify the specific constraint violated and include all relevant entities (faculty, subject, room, or time slot) involved in the violation.
**Validates: Requirements 13.1, 13.2, 13.3**

### Data Persistence Properties

**Property 22: Data Persistence Round-Trip**
*For any* configuration or timetable saved to storage, retrieving it should produce an equivalent object with all fields preserved.
**Validates: Requirements 14.1, 14.2, 14.3**



## Error Handling

### Generation Failures

**Constraint Conflict Detection:**
- When the backtracking solver exhausts all possibilities without finding a valid solution, it returns null
- The TimetableGenerator catches this and creates a ConflictReport
- The ConflictReport includes specific constraint violations detected during the last attempt
- The UI displays the conflict details to help the administrator adjust inputs

**Retry Strategy:**
- On generation failure, the system shuffles the assignment order and retries
- Maximum of 5 retry attempts with different orderings
- If all retries fail, report the most informative conflict from all attempts

**Common Conflict Scenarios:**
- Insufficient rooms for the number of classes
- Faculty availability too restrictive for required subject coverage
- Lab subjects requiring consecutive periods but insufficient consecutive slots available
- Locked slots in regeneration creating impossible constraints

### Input Validation Errors

**Configuration Validation:**
- Validate that working days is between 1-7
- Validate that periods per day is between 1-12
- Validate that at least one non-break period exists per day
- Display specific error messages for each validation failure

**Subject Validation:**
- Validate that subject name is non-empty
- Validate that weekly periods is between 1-30
- Validate that subject type is selected
- Prevent proceeding if any subject is invalid

**Faculty Validation:**
- Validate that faculty name is non-empty
- Validate that at least one subject is assigned
- Validate that max periods per day is between 1-12
- Validate that availability includes at least some time slots
- Prevent proceeding if any faculty is invalid

**Room Validation:**
- Validate that room name is non-empty
- Validate that room type is selected
- Validate that availability includes at least some time slots

### Edit Operation Errors

**Swap Validation:**
- Before applying a swap, validate all constraints
- If any constraint fails, reject the swap and display specific violation
- Highlight the conflicting cells in the UI
- Provide actionable suggestions (e.g., "Faculty X is already teaching at this time")

**Regeneration with Locked Slots:**
- If regeneration fails with locked slots, report that locked slots may be causing conflicts
- Suggest unlocking some slots or adjusting other constraints
- Allow the administrator to review and modify locked slots

### Data Persistence Errors

**Save Failures:**
- Catch and log any exceptions during save operations
- Display user-friendly error message
- Ensure partial saves don't corrupt existing data

**Load Failures:**
- Catch and log any exceptions during load operations
- Fall back to empty state if load fails
- Display error message explaining the failure

## Testing Strategy

### Dual Testing Approach

The testing strategy combines unit tests for specific examples and edge cases with property-based tests for universal correctness guarantees. Both approaches are complementary and necessary for comprehensive coverage.

**Unit Tests:**
- Focus on specific examples that demonstrate correct behavior
- Test edge cases and boundary conditions
- Test error handling and validation logic
- Test integration points between components
- Verify UI interactions and navigation flows

**Property-Based Tests:**
- Verify universal properties across all inputs
- Use randomized input generation to test many scenarios
- Each property test runs minimum 100 iterations
- Each test references its corresponding design property
- Tag format: **Feature: timetable-generator, Property {number}: {property_text}**

### Property-Based Testing Configuration

**Testing Library:**
- Use JUnit-Quickcheck for Java property-based testing
- Add dependency: `com.pholser:junit-quickcheck-core:1.0`
- Add generators dependency: `com.pholser:junit-quickcheck-generators:1.0`

**Test Configuration:**
- Minimum 100 iterations per property test (configured via `@Property(trials = 100)`)
- Each property test must reference its design document property in a comment
- Example tag: `// Feature: timetable-generator, Property 1: No Faculty Double-Booking`

**Custom Generators:**
- Create generators for domain objects: Config, Subject, Faculty, Room, ClassSection, Timetable
- Ensure generated data is valid (e.g., faculty availability includes at least some slots)
- Use realistic constraints (e.g., 1-7 working days, 1-12 periods per day)
